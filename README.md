# OnlyWorlds docs

The source of [onlyworlds.github.io](https://onlyworlds.github.io): the OnlyWorlds schema, API, SDKs and AI tools. Built with [Starlight](https://starlight.astro.build) and deployed to GitHub Pages by `.github/workflows/pages.yml`.

The Jekyll site this replaced is kept whole on the `jekyll` branch and the `jekyll-final` tag.

## Work on it

```bash
npm ci
npm run build     # gen_sdk_ref, gen_errors, astro build, then scripts/postbuild.mjs
npm run verify    # the workflows parse (verify-workflows.mjs), then the URL gate (verify-urls.mjs) on dist/
node scripts/serve.mjs   # dist/ on http://localhost:4321/, resolved the way GitHub Pages resolves it
```

Pages are Markdown in `src/content/docs/`, at the URL they are served from. The sidebar (in `astro.config.mjs`) is independent of the folders.

**Deploys.** `pages.yml` runs on every push to `main` and whenever schema-dist publishes (its publish step runs `gh workflow run pages.yml -R OnlyWorlds/onlyworlds.github.io`). A 4-hourly schedule is only a fallback: GitHub runs scheduled workflows late or not at all. Nothing uploads unless `npm run verify` passes. Push and manual deploys are tagged `docs-live-<date>-<run>`; to roll back, run the workflow on an earlier tag. An outside check watches the live site and notices if the workflow is disabled (GitHub does that after 60 days without activity) or the site falls behind schema-dist.

Run `npm run verify` before you push: a workflow file that doesn't parse never runs, and GitHub shows no failed check, only none.

## Keeping it true

Docs follow what ships, the same hour, and a weekly sweep catches the rest: `node scripts/sweep.mjs`, then the reading list and the terms in [SWEEP.md](SWEEP.md).

## Old URLs are part of the contract

The API's error responses link to `/api/errors#<code>`, the LLM guide lives at `/assets/ow_llm_guide.txt`, and tools, READMEs and AI chats link to old paths. `contract/urls.tsv` lists every one, with where it is linked from:

- **load-bearing** rows must answer 200 with the real page, on this host. Never a redirect stub: agents read the stub, not its target.
- **floor** rows are the error codes keel links to; each must be an id on `/api/errors/`.
- **page** rows are old pages nothing outside links to; a stub redirect is enough if one moves.

Two checks read that file: `npm run verify` on every build (CI and the deploy), and the outside check on the live site. A page keeps its path; to move one that the contract lists, change the contract first.

`build.format: 'file'` writes `page.html`, which Pages serves as both `/page` and `/page.html` (the old site's two forms). `scripts/postbuild.mjs` moves section pages (`<dir>/index.md`) back to `<dir>/index.html`, so `/docs/x` keeps its same-host 301 to `/docs/x/`. A directory that holds pages but none of its own (`/docs`, `/api`, `/docs/development/api`) gets a copy of the page named for it in `DIR_INDEX`, and a new one fails the build until it is named. Every other page is a file, so `/page/` answers the 404 page, which in a browser sends it on to `/page` once.

## Element pages

The field tables on the 22 element pages are generated by `scripts/gen_elements.py` from [schema-dist](https://github.com/OnlyWorlds/schema-dist), through schema-dist's own walk (imported from the checkout after it is verified against its `MANIFEST.json`, never copied). Hand-written prose stays above the marker line; everything below it is rewritten. The same run writes `contract/folder-example.json`, schema-dist's example world folder (`example/hyperion`) as the checkout holds it, with the checkout's serial, which the figure on World folders draws: one run, one checkout, so the figure and the tables are always one serial. Every deploy runs the generator on a clone of the newest `v*-dist.*` tag, so the site follows the schema without a commit here. Run it locally on a clone of a tag, never a working tree that may sit serials behind.

```bash
python scripts/gen_elements.py --dist ../schema-dist          # rewrite
python scripts/gen_elements.py --dist ../schema-dist --check  # exit 1 if a page is behind
```

## Other generated parts

- **The errors page's summary table and the contract's `floor` rows** come from keel's own list of error codes (`Error.x-ow-error-codes` in its OpenAPI), vendored as `contract/error-codes.json`. `scripts/gen_errors.mjs` runs in every build. It fails when a public code has no `### <code>` section, when a section isn't a public code, or when the Upload host errors table disagrees with the host rows. The sections themselves are hand-written. `--refresh` re-reads the live list; `--live` compares the snapshot with it (CI and the deploy warn on a difference).
- **The public page palettes** (the figure on Public worlds) come from keel's palette table (`PALETTES` and `HOUSE_PALETTE` in `worlds/public_page.py`), vendored as `contract/palettes.json` in the table's order, with the keel commit it was read at. keel is private, so the build and CI read only the snapshot. `node scripts/gen_palettes.mjs` compares the snapshot with keel's published branch (it fetches, then reads `origin/main`, never the working tree, from `../keel` or `--keel PATH`): exit 0 when it matches, 1 when stale, 2 (BLIND) when keel cannot be read. `--refresh` rewrites the snapshot from it.
- **The TypeScript page's reference** comes from the pinned `@onlyworlds/sdk` (a dev dependency): `scripts/gen_sdk_ref.mjs` reads its types with the TypeScript compiler. Bump the pin after an SDK release to move the reference.

Each one keeps to five rules:

- **Its data comes from a source at build time, never drawn by hand.** The link map reads the SDK's `FIELD_SCHEMA` (`links.mjs`); words that no source holds sit in one module (`four-nouns.mjs`) that the component and the text version both read.
- **It has a text version.** The page carries it (a list under the figure, or the figure is itself HTML text), and `scripts/postbuild.mjs` writes it into the page's Markdown twin in place of the component's tag (`FIGURE_TEXT`; a tag with no text there fails the build).
- **It takes the docs' theme**, through Starlight's colour variables, so it follows the light and dark switch.
- **Its height fits its width**, with no inner scroll: it lays out by its own width (a container query), from the phone to the content column.
- **A check holds it to its source.** `scripts/verify-figures.mjs`, first in `npm run verify`, reads the built pages: the link map against the element pages (generated from schema-dist, a second source), and the address the four nouns show parsed by the SDK's `parseOwLink`. A new figure adds its check there, watched failing on a planted error before it is trusted.

## Contributing

Issues are welcome: a bug, a wrong word, a thing you could not do. Pull requests are read; a small fix is usually taken as is, and a change to what a page does is better opened as an issue first, since it may already be built or ruled out. A reply can take a few days. A vulnerability goes privately, never in an issue: `SECURITY.md`. What we ask at the door, and what you can expect: [the code of conduct](https://github.com/OnlyWorlds/OnlyWorlds/blob/main/CODE_OF_CONDUCT.md). The field descriptions on the element pages are the schema's own text, so raise a change to one on [the standard's repository](https://github.com/OnlyWorlds/OnlyWorlds) rather than here; the next deploy picks it up.
