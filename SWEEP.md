# The docs sweep

The docs state facts that other people's work changes: the API, the MCP server, the SDKs, the schema, the tools. Two habits keep them true.

**1. Docs follow what ships, the same hour.** When something the docs describe ships, its owner tells the docs' maintainer (Kael) with the commit; the page changes and deploys that hour, not at the next sweep. What counts: a new or changed route, field, error code or limit (keel); a new schema-dist serial; a new SDK, Python, Unity or Atlas version; a changed tool, link or name. The generated parts follow on their own (element tables from schema-dist at each build, error codes from keel's list, the TypeScript reference from the pinned SDK); the hand-written pages are the ones that need a person. A new keel error code is the exception that needs both: `node scripts/gen_errors.mjs --refresh` and its `### <code>` section the same hour, because keel's `doc_url` already points at that anchor (every 410 linked to a missing `#gone` until docs-next 12e90a0, 2026-10-18; CI only warns). A changed palette in keel's `worlds/public_page.py` is followed the same way: `node scripts/gen_palettes.mjs --refresh`, then the build; keel is private, so CI never sees it, and the sweep's check 2b reads it only on a machine with keel's checkout. A keel route added, removed or given other credentials is followed with `node scripts/gen_callers.mjs --refresh` the same hour: `npm run verify` prints STALE when the credentials figure's snapshot differs from the live API document, and the sweep's check 2c fails on it. A change to Sign in with OnlyWorlds (the authorize page's parameters, the token route's fields or answer, the code's lifetime) is followed with `node scripts/gen_signin.mjs --refresh`: verify prints STALE for the sign-in figure's snapshot, and the sweep's check 2d fails on it and on the document disagreeing with keel's code. The same commit adds the change's dated line to `/docs/changelog` (one entry stood for 161 commits until docs-next 1879d09, 2026-10-20). **Every change to the server that is not internal is followed within a day of its merge**: a dated line in `changelog.md` for what it moved, and a record in the maintainer's follow log either way, including "no docs change" when the docs describe nothing it moved. The server's repository is private, so the changelog names what changed, never the change's number there. The marker is what Boss's weekly reader checks against keel's merged PRs (2026-10-20); it stays a comment, hidden on the page and visible in the page's Markdown copy. Commit subjects stay free.

**2. A sweep every week**, because the first habit misses what nobody thought to mention. `node scripts/sweep.mjs` does the measurable part and lists what moved; a person reads the rest. A status check marks the sweep overdue by itself after two weeks without a run. The cadence can slacken once the docs stop moving fast.

## The procedure

1. **Run it.** `node scripts/sweep.mjs` (add `--no-links` for a quick one). Fix every STALE it prints: bump a pin, refresh a snapshot, mend a link, replace a word, follow a release (a changelog line that links its page and names its version, a serial by its number, or `<!-- <repo> <tag>: no docs change -->` when it moved no claim).
2. **Read MOVED against the pages that state it.** Each commit line names a source; the page to read is:
   - keel: `docs/development/api-reference.mdx`, `api/*` (reads, writes, links, changes, errors, images, members, cors), `mcp.md`, `agents.md`, the error table, `schema/worlds.md`
   - schema-dist: `schema/*`, `schema/conventions.md`; the element tables regenerate on their own
   - `@onlyworlds/sdk`: `typescript.md`, `packages.md`; its README is the repo's, kept in step by hand
   - the Python package: `python.md`; Atlas: `tools/atlas.md`, `getting-started/*`; Unity: `unity.md`, `games.md`; Obsidian: `tools/obsidian-plugin.md`
   - A link that sends the reader elsewhere for a claim: open the target and find the claim there. The link check sees that the page exists, not what it says (agents.md sent readers to Writes for the agent mark, which Writes never mentioned, 2026-10-18).
3. **Read for language** (Titus's two standing complaints, 2026-10-09): OnlyWorlds explained again where a page has no need to; the 22 categories listed again; words that are not OnlyWorlds elements (a faction, an item, a realm) used as if they were. `sweep.mjs` names the pages that restate the 22 and flags the words it knows.
   Every page is edited here (since 2026-10-18, Titus's word: the content lane is Kael's whole; Skeld's content folder no longer syncs). Skeld brings facts: a keel change that moves a page's claim comes to the docs' maintainer the hour it ships, and the page follows that hour.
4. **Run `npm run build && npm run verify`,** push, check the deploy. A code block that was added or changed is run as extracted from the page source, never retyped: a Write example run from my own script passed while the page's copy lacked its import (2026-10-18).
5. **Walk the living map of sharing** (the maintainer's map of every sharing route, kept outside this repository; its check runs with `--write`). A DRIFT (a row names a route keel no longer has) is fixed in the map's `rows.json` before the stamp. Its findings (a sharing route with no row, a route nothing classifies, a row with no walk or no control, a walk older than two weeks) are the sweep's walking list: re-walk what the docs' pages lean on, and route the rest to the row's owner.
6. **Stamp it below** and report the sweep in one line: what was stale, what was fixed, what is open.

## The terms (one place)

- **"the standard"** names the thing, for people. **"schema"** only for the files (`schema/*.yaml`, schema-dist) and the reference pages about them.
- Elements are the 22 categories: Character, Creature, Species, Family, Collective, Institution, Location, Object, Construct, Ability, Trait, Title, Language, Law, Event, Narrative, Phenomenon, Relation, Map, Pin, Marker, Zone. A game's own words go on the left of a mapping table, never in prose as if they were ours.
- The Python package is on PyPI since 2026-10-11: `pip install onlyworlds`. The old install line from GitHub (`git+https://…/python-sdk`) is a sweep check.
