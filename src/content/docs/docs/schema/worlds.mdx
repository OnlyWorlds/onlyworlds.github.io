A world is the top-level container for elements, representing a complete setting at any scope you define. Every element belongs to exactly one world, and a world key reads or writes exactly one world.

## Core

| Field | Type | Required | Description |
| :--- | :--- | :--- | :--- |
| `id` | string (uuid) | No (server-assigned) | Unique world identifier (UUIDv7) |
| `name` | string | Yes | Display name; it cannot be empty |
| `description` | string | No | Text description |
| `image_url` | string (url) | No | Cover image or representative visual |
| `public_read` | boolean | No (default `false`) | Whether the world can be read by anyone, without a credential. On onlyworlds.com the owner sets it on the world page, and anyone then reads the world with no key ([Public worlds](/docs/development/api/public)) |
| `created_at` | string (date-time) | No (read-only) | When the world was created, as the tool holding it recorded it |
| `updated_at` | string (date-time) | No (read-only) | When the world's own settings (name, description, image, time and units) last changed |

## Timeline

| Field | Type | Required | Description |
| :--- | :--- | :--- | :--- |
| `time_format_names` | array of strings | No | Names of each time step: `["Day", "Week", "Month", "Year"]`, or custom names like `["Sol", "Cycle", "Season", "Era"]` |
| `time_format_equivalents` | array of integers | No | Basic units per step, e.g. `[1, 7, 30, 365]` (older worlds on onlyworlds.com may hold them as strings) |
| `time_basic_unit` | string | No | The unit every date counts in (e.g. `"Year"` or `"Day"`) |
| `time_range_min` | integer | No | Earliest tracked time point |
| `time_range_max` | integer | No | Latest tracked time point |
| `time_range_current` | integer | No | The world's now, its current time point, as the API names it. The standard's YAML and a [world folder](/docs/schema/folders#worldjson) name it `time_current`. |

Element fields that hold a moment, such as a Character's `birth_date` or an Event's `start_date`, are integers in the world's time units.

A world's own calendar, its months, leap days and eras, is the [`atlas_calendar`](/docs/schema/profiles#calendar) profile: it names points on this line and changes no date.

### Timeline examples

**Fantasy world with a custom calendar:**
- `time_format_names`: `["Sun", "Tenday", "Moon", "Turning"]`
- `time_format_equivalents`: `[1, 10, 30, 360]` (a Tenday is 10 Suns, a Moon 30, a Turning 360)
- `time_basic_unit`: `"Sun"`
- `time_range_current`: `448560` (the first Sun of Turning 1247, counting Turning 1 from 0: 1,246 × 360 Suns). Every date counts in the basic unit, so a world that only tracks years makes its basic unit the year.

**Science fiction setting with stardates:**
- `time_format_names`: `["Cycle", "Rotation", "Orbit", "Epoch"]`
- `time_basic_unit`: `"Cycle"`
- `time_range_min`: `0`
- `time_range_max`: `128256`

Timeline fields work with [Events](/docs/schema/element_categories/event) and [Narratives](/docs/schema/element_categories/narrative).

## Units

Some element fields hold a measure: a Character's `height` and `weight`, a Creature's `speed`, a Location's `elevation`, an Ability's `range`. The numbers are whole, and the world says what they count in, with three optional free-text settings:

| Field | Type | Counts | Used by |
| :--- | :--- | :--- | :--- |
| `length_unit` | string | Lengths | Character and Creature `height` |
| `mass_unit` | string | Masses | Character, Creature, Object and Species `weight` |
| `distance_unit` | string | Distances | Ability `range`, Creature `speed`, Location `elevation` |

The value is free text, written as the world means it. Recommended where one fits: `mm`, `cm`, `m`, `in`, `ft` for lengths; `g`, `kg`, `t`, `lb` for masses; `m`, `km`, `ft`, `mi` for distances. A world's own unit (`hands`, `stone`, `leagues`) is shown as written, and nothing is converted: a tool can convert what it recognises and shows the rest verbatim. Empty means not set. A number stays a bare number in the element; only the world names its unit.

## Platform fields

onlyworlds.com adds fields of its own to the world it serves, part of the platform, not the standard. Each is described with the [world read](/docs/development/api/reads#the-world).

| Field | Type | Description |
| :--- | :--- | :--- |
| `owner_character` | string (uuid) or null | The owner's own Character in this world ("this Character is me"), or null |
| `agent_narrator_rule` | boolean | The switch holding agent seats to their own narrator |
| `agent_writes_proposed` | boolean | The switch under which an agent seat's changes become [proposals](/docs/development/api/proposals) |
| `slug` | string or null | The address of the world's public page, null while the page is off |
| `public_page` | object | The public page's settings |
| `origin` | object | Where the world first came from, `{source, producer}` |
| `counts` | object | How many elements the reader may read, in all and by element type |

The world named by a key is `GET /api/v2/world/`. Its owner changes it with `PATCH`; the writable fields are `name`, `description`, `image_url`, the timeline fields, the three unit settings, `owner_character`, the world's extension keys (`x_`, `atlas_`, `shadow_`) and the provenance lines `source` and `producer` ([the world's writable fields](/docs/development/api/writes#the-world)). A co-builder may send every writable field but `owner_character`. `public_read` and `agent_narrator_rule` (the platform's switch holding agent seats to their own narrator, set on the world page) cannot be changed through the API.
