New to OnlyWorlds? [Your first hour](/docs/getting-started/first-hour) reads a world, writes to the practice world and deletes again, in one short page. This page covers the whole package.

`onlyworlds` is the Python package for OnlyWorlds. It reads and writes the world folder format, pushes a folder's changes to a world, and has a client for the REST API v2. It needs Python 3.12 or later and has no runtime dependencies.

The element types and the kind of every field are generated from [schema-dist](https://github.com/OnlyWorlds/schema-dist), never listed by hand. The package's version is its own and does not track the schema's.

## Install

```bash
pip install onlyworlds
```

Releases are on PyPI, each listed in the [changelog](https://github.com/OnlyWorlds/python-sdk/blob/main/CHANGELOG.md). Until 1.0, the interface can still change between minor versions.

## Read a world

```python
from onlyworlds import Client

client = Client("0000000001")  # the public demo key for Moppetopia; your own world's ow_r_ key works the same, no PIN
for character in client.iter_elements("character"):
    print(character["name"])
```

This runs as written. A write key also takes a PIN: `Client(key, pin)`. The PIN is a 4-digit number (1000 to 9999) set on your account in account settings, and it guards writes to every world you own. A member writes with their own account PIN, and an AI seat sends its seat secret (`ow_s_…`) as the PIN. The client sends it only where the server checks it (since 0.27.0): on writes, on `me()`, and on every call with a 10-digit legacy key; a prefixed key's reads go without it.

Elements are plain dicts. Two demo keys read public sample worlds: `0000000000` (Hyperion) and `0000000001` (Moppetopia). `client.search("Fluffington", limit=200)` finds the elements whose name or text holds every word you give ([Search](/docs/development/api/reads#search)).

`client.get_world()["counts"]` says how many elements the key may read, in all and per type: `{"total": …, "types": {"character": …, "location": …}}`. `client.get("character", element_id)` reads one element. To keep a whole world as files, `export_world("moppetopia", api_key="0000000001")` writes it as a folder (one that does not exist yet), and `read_folder("moppetopia")` reads it back; both are imported from `onlyworlds`.

## Write

The example reads the write key and PIN from the environment. These two are the [practice world](/docs/getting-started/keys#the-practice-world)'s, which anyone may write to and which goes back to the same copy every night; for your own world, put in its `ow_w_` key and your PIN.

```bash
export OW_API_KEY=ow_w_QRRMlAFPF9vPZSqmiV6QJm2HDJH_sP28x2RccPmYP1A
export OW_API_PIN=1234
```

```python
import os
from onlyworlds import Client

# the write key and its PIN from the environment (OW_API_KEY, OW_API_PIN), never in the code
writer = Client(os.environ["OW_API_KEY"], os.environ["OW_API_PIN"])

ranger = writer.create("character", {"name": "Ilse the Ranger"})
peak = writer.create("location", {"name": "Dragon Peak"})
writer.patch("location", peak["id"], {"supertype": "Mountain"})

# add or remove links on a multi-link field without replacing the list
writer.edit_links("location", peak["id"], "founders", add=[ranger["id"]])

# read one back, then delete it
print(writer.get("character", ranger["id"])["name"])
writer.delete("character", ranger["id"])
```

`delete` removes the element and takes its id out of every link to it. A read of it afterwards raises `ApiError` with `status` 410 and `code` `"gone"`, not a 404.

A body the client will not send raises before anything is sent, and is never retried: `TypeError` for a value JSON cannot hold (since 0.158.1), and `ValueError` for a number that is not finite, named with its place (since 0.158.2), or a body nested more than 256 levels deep, which the server does not read (since 0.158.3).

`create` gives an element without an `id` one, and always sends an `Idempotency-Key`. So retrying a create after a lost answer is safe: it replays the stored result instead of making a second element. `patch` replaces every field it sends, and a list replaces the whole list. Use `edit_links` to add or remove links. `bulk` takes up to about 1,000 `{"type", "element"}` items: it succeeds partly by default (check each slot's `status`), or all or nothing with `atomic=True`.

Since 0.43.0 `create`, `upsert` and `bulk` send `hidden` as the element carries it, so an element hidden in a folder is [created hidden](/docs/development/api/hidden#creating-an-element-hidden) from its first moment. Before, they stripped it and such an element was created visible: a behaviour change. Only the owner's keys and a co-builder's may send `true`; any other key gets a 403 `hidden_not_allowed` (`ApiError.is_hidden_not_allowed`; in `bulk`, that slot's 403) and nothing is created. An update never sends it: `patch`, `propose` and `push` strip it as before.

If your script is an AI agent, say so: `Client("ow_w_...", "1234", agent=True)` (since 0.3.0) sends `X-OW-Agent` on its element writes, and OnlyWorlds records your writes as an AI's. A tool people use leaves it off. Each element read carries `changed_by` and `changed_via`, the last write's member and door (`seat`, `mcp` and `declared` are the doors marked as an AI's). See [Agents](/docs/development/agents).

Name your tool: `Client("ow_w_...", "1234", client="atlas")` (since 0.21.0) sends `X-OW-Client` on every element write (and on a proposal, its accept and a review), never on a read or another write, and OnlyWorlds keeps the name on the element as `changed_client` ([a write can name its client](/docs/development/api/writes#agent-writes)). The default is `python`; a name outside lower case letters, digits and hyphens, 1 to 32 characters, is a `ValueError` at construction. `changed_client` and a tombstone's `deleted_client` are read-only and never pushed.

## A world as a folder

`export_world` saves the world a key reads as a [world folder](/docs/schema/folders), one JSON file per element. `push` sends back what you changed: it compares the folder with a baseline, an untouched copy of the same export, and patches only the fields that differ. With the practice world's key and PIN in the environment, as above:

```python
import json
import os
import shutil
from pathlib import Path

from onlyworlds import Client, export_world, push

key, pin = os.environ["OW_API_KEY"], os.environ["OW_API_PIN"]

# save the world as a folder, and keep an untouched copy beside it: the baseline
export_world("world", api_key=key, pin=pin)
shutil.copytree("world", "baseline")

# change one field in one element's file
path = sorted(Path("world/elements/character").glob("*.json"))[0]
element = json.loads(path.read_text(encoding="utf-8"))
element["description"] = "Edited on disk."
path.write_text(json.dumps(element, indent=2, ensure_ascii=False) + "\n", encoding="utf-8", newline="\n")

# send what differs from the baseline: one PATCH carrying one field
result = push("baseline", "world", api_key=key, pin=pin, log_path="push.log")
print(result.planned, "planned,", result.ok, "sent")

print(Client(key, pin).get("character", element["id"])["description"])
```

It prints `1 planned, 1 sent` and then `Edited on disk.` `export_world` writes only to a folder that does not exist yet, and a read-only key such as the demo key `0000000001` exports without a PIN. `log_path` is required: the log is what lets a rerun skip what already landed. A push creates and deletes nothing; what it does with a new file, an empty field or a hidden element is under [Push](#what-it-covers) below.

## Follow changes

```python
walk = client.walk_changes(saved_cursor)  # None for everything
for op in walk:
    ...  # op["op"] is "upsert" or "delete"
saved_cursor = walk.cursor  # opaque: persist it, never parse it
```

To poll cheaply, `client.head()` (since 0.22.0) reads `GET /changes?head=true` and answers `{head, cursor, epoch, unchanged}` without reading any element. The poll is conditional: the client keeps the `ETag` of its last `200` and sends it back as `If-None-Match`, so an unmoved head is a `304` keel does not count against your budget, answered as the head it holds with `unchanged=True`; a `409` clears the tag. Walk only when `head` or `epoch` differs from what you last applied, so a walk that failed is walked again on the next tick.

A delete's `op["reason"]` is `deleted`, or `hidden` for an element [hidden](/docs/development/api/hidden#the-feed) from the key: remove it from your copy either way. If the feed refuses a cursor (`is_resync_required` on the error), walk again from the start and keep what your copy holds that the new walk does not name. The error's `resync_reason` says which: `"role"` (your own role or membership moved), keep it; `"view"` (something left your view), drop it. A tool never empties a copy on its own ([What a reset keeps](/docs/development/api/changes#what-a-reset-keeps)). See [Sync with changes](/docs/development/api/changes).

## Export to OKF

Since 0.6.0 a world folder can be exported as a valid [Open Knowledge Format](https://github.com/open-knowledge-format/open-knowledge-format) (OKF) bundle, 0.3 since 0.158.0 (0.2 before), as that spec stands at one pinned commit (`onlyworlds.okf.OKF_COMMIT`). The bundle's root index carries the world's name as its `title` and a one-sentence `description`. It needs the `okf` extra, which adds PyYAML; the rest of the package stays dependency-free.

```bash
pip install "onlyworlds[okf]"
python -m onlyworlds.okf my-world my-world-okf
```

Each element becomes one markdown file: its fields and links in the frontmatter, its text under headings, its links again as markdown links (in-prose `ow://` references included, in every [address](/docs/schema/profiles/addresses) form that names one of the world's elements since 0.74.1: with a moment, a lens, or the world's own id, and since 0.124.0 only a type word that is one of the 22 in lowercase; one to another world stays as written). The World becomes `world.md` (without its `api` block), and there is an index per type and one for the bundle. A [known-of](/docs/schema/folders#known-of-elements) stub keeps `known_of: true` in its frontmatter (since 0.10.2), so it never reads as a whole element. Since 0.43.0 a [hidden](/docs/development/api/hidden) element (any value of `hidden` but absent, `null` and `false`, the test `folder.is_hidden`) is left out unless `--hidden` (`hidden=True` on `build_bundle` or `export_okf`), since a bundle is handed on: no file, no index line, every link to it left out (never a `urn:uuid:`), an in-prose reference reduced to its own label, and the count in `OkfReport.hidden_left_out` and in world.md's `onlyworlds_export` block. Kept, its frontmatter carries `hidden: true` and every link and index line to it says `(hidden)`. A world with no hidden element exports byte for byte as before. The same folder always gives the same bytes, and anything left out is listed in the report (on stderr from the command line). A bundle is a copy to read elsewhere, never a folder to sync: it carries no `change_seq`, no record of who wrote what, and not the world's key.

## Proposed changes

Since 0.26.0 a member can [propose a change](/docs/development/api/proposals) for a keeper to accept instead of writing it, and a world's owner can make every AI seat work that way.

```python
row = client.propose("character", cid, {"reputation": "Feared"}, evidence="Chapter 12", expires=None)
page = client.world_proposals(state="open")              # newest first; keepers see every row, others their own
for p in client.walk_world_proposals(state="open"): ...  # every page
accepted = client.accept_proposal("character", cid, row["id"])   # {"proposal", "element"}: the keeper's own write, one feed row
client.decline_proposal("character", cid, row["id"], reason="not yet")
client.withdraw_proposal("character", cid, row["id"])   # the proposer's
client.review_new_element("character", eid, "accept")   # a seat's new element: accept clears the mark, "decline" deletes it
```

Since 0.35.0 the queue holds two kinds of row, told apart by `kind`: proposals (`"proposal"`, `fields` only what differs, `omitted` what a `PUT` left empty) and a seat's marked new elements (`"new_element"`), settled with `review_new_element`; an unmarked element raises an `ApiError` with `is_not_proposed`. The walker sends `next_cursor` back as it came.

`propose` cleans its fields as `patch` does and always sends an `Idempotency-Key`; `accept_proposal` sends none, as the document declares none. With **AI seats propose, a person accepts** on for the world (`agent_writes_proposed` on `get_world()`, read-only; `patch_world` drops it), an AI seat's `patch`, `upsert` or link edit answers `202` and the client raises `ProposedError` (`err.is_proposed`, `err.proposal`) rather than returning a body that is not the element; a `bulk` slot with `status` 202 stays in the result, listed on `BulkResult.proposed`; `push` counts a 202 as `proposed`, never as pushed, and never files the same proposal twice. An accept that finds a proposed field moved raises `StaleProposal` (409, `.conflicts`, `.current`); the other codes are `is_own_proposal`, `is_proposed_only`, `is_too_many_open` and `is_field_not_visible`. The [doctor](#check-a-world)'s flag 12 reports the queue's open and lapsed rows through the API.

## The Markdown pack

Since 0.25.0 a world can be packed as a few merged Markdown files for an AI notebook that caps its sources: NotebookLM (50 sources a notebook, 500,000 words a source) and Claude Projects (30 MB a file). No extra is needed.

```bash
python -m onlyworlds.pack my-world my-world-pack                     # a world folder
OW_API_KEY=... python -m onlyworlds.pack --api my-world-pack         # an account world; a read key needs no PIN
python -m onlyworlds.pack my-world OUT --rooms --extensions          # keep room elements and x_ fields
python -m onlyworlds.pack my-world OUT --proposed                    # keep unreviewed AI elements, labelled
python -m onlyworlds.pack my-world OUT --hidden                      # keep hidden elements, labelled (0.43.0)
```

`00-world.md` opens with a line saying which kind of key made the pack (since 0.26.1: the owner's, a member's with its role, a Character's view, or the public view; from `/me` or the folder's `exported_as`, no line when neither says, never the key: a pack holds only what its key was served), then holds the world's own fields and an index of every element by type (name, supertype and subtype, the first sentence of the description); then one file per element type present, in schema order, each element a `## Name` section with its id, its fields in schema order as `**Field:**` paragraphs, and every link written as the name and type of the element it points to, so a reader needs no other file to follow it. Prose is escaped so a line inside a field never reads as a heading. A [known-of](/docs/schema/folders#known-of-elements) stub carries one line saying that only the fields shown are known. [Room](/docs/schema/profiles#room) elements are left out unless `--rooms`, and `x_*`, `atlas_*` and `shadow_*` fields unless `--extensions`; the command's sentence counts both. A file past `--words` (400,000) or `--bytes` (25,000,000) splits at element boundaries into numbered parts; when the parts would pass `--files` (50), the smallest adjacent whole files merge into one named by their types; an element larger than a cap is written alone and named, never cut or dropped. Only a pack that cannot meet `--files` exits 1, and every file is still written. The same world gives the same bytes. Beside it: an [OKF bundle](#export-to-okf) is one file per element with frontmatter and links as paths, for a knowledge tool that follows links; the pack is merged prose for a notebook that reads it whole.

A world with its own words for the types (the [names profile](https://github.com/OnlyWorlds/schema-dist/blob/main/profiles/names.md), `x_names` in `world.json`) is packed in them, the standard's name in brackets for the AI reading it: `### Employees (Character)`, `*AI agent (Character, Agent) · id …*` (since 0.31.0). File names and links keep the standard's type, and the map itself is never printed among the world's fields.

An element marked proposed that no keeper has settled yet (it carries [`x_review_proposed`](/docs/development/api/proposals) with a value, whoever wrote the mark) is not canon, so since 0.36.0 the pack leaves it out unless you pass `--proposed` (`proposed=True` from Python). `00-world.md`'s opening lines say how many were left out, as "marked proposed and not yet reviewed by a keeper" (since 0.117.1). A kept one is labelled "proposed, not yet reviewed" under its id line, on its index line and on every link to it, and a link to one left out names it with the same label. This is the reader rule for any tool that hands a world on to an AI: an unreviewed element passed on as canon is where a planted instruction would get through.

A [hidden](/docs/development/api/hidden) element is hidden from whoever the world is handed to, never from its holder, and a pack is handed on: since 0.43.0 the pack leaves one out unless you pass `--hidden` (`hidden=True` on `build_pack`, `pack_world`, `pack_folder` and `pack_api`). `00-world.md`'s opening lines count what was left out (`*1 hidden element is left out of this pack.*`), as do `PackReport.hidden_left_out` and the command's line. Unlike a proposed element, one left out is never named: a link to it is left out (`PackReport.hidden_links_left_out`) and an in-prose reference keeps only its own label. A kept one is labelled `hidden` under its id line, on its index line and on every link to it (`Cy (character, hidden)`). A world with no hidden element packs byte for byte as before. `export_world` and `write_folder` copy a world and keep the mark.

## Check a world

The doctor (since 0.11.0) reads a world and reports what its keeper should look at, each finding with the element and the reason. It never writes: no file, no API write; its only product is the report.

```bash
python -m onlyworlds.doctor PATH/TO/WORLD-FOLDER          # a folder
OW_API_KEY=... OW_API_PIN=... python -m onlyworlds.doctor --api   # an account world; a read key needs no PIN
python -m onlyworlds.doctor PATH --json                   # the same report for a tool
python -m onlyworlds.doctor PATH --packet                 # the findings as work packets (0.12.0)
```

What it checks: a link to an element that is not there; an Event ending before it starts; an element with no links in or out; two elements whose names collide once folded (within one type); a known-of stub never filled, and an element with no text in any of its type's text fields (a Law's text is in `declaration` and `purpose`, a Narrative's in `story`, so `description` alone is never read); a charter untouched after many changes (through the API); the world's own house rules (since 0.24.0: the [checks profile](/docs/schema/profiles#checks), `x_checks_rules` on the Charter: each rule's sentence with how many elements it scoped and which fall short, and a rule the doctor cannot apply named as not checked, never passed; only the world's Charter counts: since 0.82.0 the newest marked Charter (the [charter profile](/docs/schema/profiles#charter)), through the API the one keel names in [`front_door`](/docs/development/api/members#the-front-door), and every other marked Charter is reported with its rules not applied; only a keeper sets the mark, so a seat cannot write the rules it is judged by); a world that maps a software ecosystem (since 0.45.0, on a world whose elements carry `x_spine_` keys: each element read under the [spine profile](https://github.com/OnlyWorlds/schema-dist/blob/main/profiles/spine.md), an off-list kind, a value the reader left out and a probe off the probe form named, then each row kept by exactly one Seat through the Title's field for the row's own type, every `x_spine_depends_on` id in the world, a `legacy` or `provenance` row named by an Event with supertype `Retirement` in `x_spine_retires` and linked through its typed field where the type has one (a Law by the key alone, since 0.48.0), a row still at `gone`, and no two rows of one type sharing a name once folded; on a projection, a World carrying `x_spine_projection` (its `source` a world's UUID, its `at` an ISO time), only the projection's checks run: `x_spine_owner` on every row and nothing hidden; whether a probe passes is named as not checked); and, on a folder, a stale `format_version` and a key committed in a tracked `world.json`. Each flag says how much it could compare, and a flag that cannot run on that door is listed with its reason, never counted as clean. Findings on messages and room things are listed apart and kept out of the headline count: a message by the [message profile](/docs/schema/profiles), a room element by the room profile's type and supertype pairs (`Work item`, `Report`, `Board` and the like) together with its mark `x_room_of` (since 0.118.0). A room pair without the mark is read as lore by every tool, so a finding on it counts with the rest; a house rule that asks for the mark lists each element made without it. Exit code 0 when clean, 1 with findings, 2 when nothing could be read. The judgement half, re-reading a claim against its source, is a separate recipe that takes the doctor's findings as its targets.

On a folder, the report first names what it could not read as an element (since 0.142.0; `unread` in `--json`, each entry a `file` and a `why`): a file that is not JSON, is not an object or has no `id`, a file whose extension is `.json` in another spelling (`M.JSON`, since 0.145.0), a second file of one id, a directory that is no type's (the type word in lower case, since 0.145.0). Every check ran on the rest, so an element in such a file counts as not there and a link to it is listed as a link to a missing element. Any unread file makes the exit code 1. Three kinds of file are read the same way, on every platform: one holding a value nested more than 200 deep, one holding an integer of more than 4,300 digits, and (since 0.143.0) one holding a number that is not finite, `1e400` or `NaN`.

The lint (since 0.51.0) checks a world folder's shape rather than what it says: a file outside the 22 type folders, a missing or duplicate `id`, a key that is not a field of its type, a value of the wrong shape, a link that does not resolve inside the folder or points at the wrong type.

```bash
python -m onlyworlds.lint PATH/TO/WORLD-FOLDER
```

It is schema-dist's own [folder checker](/docs/schema/folders#rules-for-tools), carried inside the package at its schema pin, so it gives the same report as the dist's command and needs no YAML library or copy of the repository. One line per problem, then the count it checked; exit 0 when clean, 1 with problems, 2 when the folder is not a world folder, 3 when nothing it read has a problem but a file was not read. A file whose JSON Python cannot hold (nested too deep, or a number too long) gets one line saying it was not read, and the check goes on (since 0.152.0). From code, `onlyworlds.lint.lint(folder)` returns the report.

`--packet` (since 0.12.0) prints the same findings as work packets, the `packet` extension profile ([schema-dist `profiles/packet.md`](https://github.com/OnlyWorlds/schema-dist/blob/main/profiles/packet.md)): a JSON array of Relations with supertype `Work item` and no `id`, each with one entry per element under `x_packet_elements` (`{type, id, reason}`, in flag order), the same ids on the Relation's typed link fields, `x_packet_source` (`{server, world}`, the server `null` for a folder) and `x_packet_producer` (`onlyworlds doctor` and its version). Empty when clean; split past the extension cap into `(i of n)` packets. Findings on messages and room things, and a finding on the world itself, stay in the report. A tool that lands a packet in a world or a parlor mints its id; the doctor still writes nothing.

## What it covers

- **World folders**: `read_folder` and `write_folder` implement the folder format (v0.3.25 since 0.155.0, `FORMAT_VERSION`; a folder's existing stamp is kept, older stamps read as before). A world's `origin` is carried as given, from `GET /world` or a read `world.json`, and never derived. An export writes the [`producer` line](/docs/schema/folders#worldjson) as the folder's maker (`{"tool": "onlyworlds", "version", "input": "server"}`); a tool that runs the export in its own name passes `producer=` with its own line. A folder written from another folder keeps the line it carries. Since 0.37.0 `push` sends nothing for an element whose folder copy carries `hidden: true` while the server's does not, and names it in `PushResult.hidden`: the server takes the hidden mark only through its own route, so a patch would edit an element every reader still sees. `patch_world` never sends the folder-only keys (`format_version`, `source`, `exported_as`, `producer`, `writable`, `api`, `snapshot_*`) and pass its shared conformance fixture. Since 0.9.0 a [known-of](/docs/schema/folders#known-of-elements) stub is written without its unset fields (since 0.10.0 with every field it was served with a value, such as a Character's public fields; `PUBLIC_FIELDS` lists them per type), flagged on read (`folder.known_of`, `is_known_of`), never pushed (`PushPlan.known_of` lists it), and refused by the client's writes before anything is sent. The reader never changes a folder. It skips a file that is not JSON, not an object or has no `id`, and since 0.5.1 a dot-prefixed file in a type folder (a tool's litter, not an element); `folder.skipped` lists each with the reason. An element found in both the current `elements/` layout and Atlas's older `spatial/` one is served from `elements/`, and `folder.in_both_layouts` lists it (since 0.5.0).
- **Archives** (since 0.17.0): `read_world_file(path_or_bytes)` opens a `.owworld` file as the [folder format](/docs/schema/folders#folders-and-onlyworldscom)'s archive rules say (the directory checked before anything is inflated; a refusal is `WorldFileError` with `reason` one of the thirteen causes, under the same names as the TypeScript SDK's, and since 0.156.0 a `not_a_world` whose `world.json` is there but cannot be read carries `world_fault`, `too_deep`, `not_json` or `number_out_of_range`; since 0.45.1 two names that are one after NFC and simple case folding are compared at Unicode 15.1, built from Unicode's own files rather than the interpreter's, and the NFC is exported as `onlyworlds.worldfile.nfc`) and `.to_folder(dest)` writes it out as a folder; `write_world_file(folder, path, top_dir=None, private_dir=None)` and `world_file_bytes(folder)` write one: the `mimetype` marker first and stored, every entry stamped 1980-01-01 in UTF-8 byte order, only `world.json`, `elements/`, `spatial/`, `media/`, `records/` and the one dot-folder named in `private_dir`, the same folder giving the same bytes (within one zlib build). From 0.32.0 the records a producer marks `"private": true` in `records/RECORDS.json` stay home: left out whole, `RECORDS.json` kept as it is, unless `include_private_records=True`; a manifest it cannot read raises `ValueError` unless you pass that ([private records](/docs/schema/folders#folders-and-onlyworldscom)). From 0.43.0 both take `include_hidden=True`: a world file is a copy, and a [hidden](/docs/development/api/hidden) element's file travels byte for byte. For a file made to hand to someone else, `include_hidden=False` leaves every element file (one directly in a type folder of `elements/` or `spatial/`, since 0.90.1 only those) whose JSON object carries the mark out whole, nothing else rewritten (a link to it keeps the id, which dangles); a list passed as `hidden_left_out=` receives the left-out files' paths, sorted, so its length is the count. From 0.90.0 a world file leaves out who wrote each element: `created_by`, `changed_by`, `changed_via`, `changed_client` and `doors` leave every element file that holds them, which is written in the folder's own form (two-space indent, a trailing newline, its other keys in their order); `include_author_fields=True` writes every file byte for byte, for an archive of your own world. A push creates nothing and never sends the hidden mark: it patches only elements already in the baseline (an element only in the folder is listed as `only_in_folder`), so an element new to the server goes through `create`, `upsert` or `bulk`, which since 0.43.0 send `hidden: true` as the folder has it. Since 0.155.0 a push never sends `date_labels`, the key the [MCP server](/docs/development/mcp#dates-in-the-worlds-words) gives a date's words under, so a body copied from it plans as if the key were not there. A world's `origin` is its birth line, written once: since 0.34.0 a push sets it from the folder's `source` and `producer` only on a first fill from a folder made elsewhere (the world's `origin` empty, the folder not exported from this same world), never over a first import; a key that may not write the world (a contributor's) skips it without failing the push (`PushResult.origin` holds what was set).
- **Client** (`patch_world` takes back a `get_world()` body, `origin` stripped, and sends extension keys as given; a folder `world.json`'s own `source` and `producer` it leaves out, and `source=` and `producer=` send them when you name them, since 0.35.0): `health`, `get_world`, `patch_world`, `list_page`, `iter_elements`, `get`, `create`, `upsert`, `patch`, `delete`, `edit_links`, `bulk`, `changes`, `head` and `walk_changes`; `me` ([Who am I](/docs/development/api/members#who-am-i)), `draught` ([The draught](/docs/development/api/draught)), `world_lenses` and `set_my_lenses` ([Lenses on the API](/docs/development/api/lenses)), and `propose` with the proposal calls ([Proposed changes](/docs/development/api/proposals)). `create` and `bulk` always send an `Idempotency-Key`, so a retry after a lost answer is safe: it never creates an element twice. A retry that meets the first request still running (409 `idempotency_in_flight`) waits and tries again until the stored answer replays (since 0.4.0). The client retries a 429 (never `rate_limited`, a wrong PIN), a 5xx and a lost answer itself, waiting `Retry-After` when one is sent, up to 6 tries in all by default; `Client(key, pin, retry=RetryPolicy(attempts=1))` turns it off. The TypeScript SDK never retries, on purpose.
- **Errors**: `ApiError` carries the envelope's `code`, `param` and `doc_url`, with flags such as `is_id_conflict`, `is_not_author`, `is_resync_required`, `is_idempotency_in_flight`, `is_validation_error` and `is_hidden_not_allowed` (since 0.43.0: a create carried `hidden: true` from a key that may not hide, and nothing was created). Since 0.158.0 `limit` reads which size limit a write passed, a key of the API document's `info.x-ow-limits`, with `is_element_too_large`, `is_element_too_many_links` and `is_extensions_too_large`: the API is adding that key to the code `invalid_request` of its [size refusals](/docs/development/api/writes#field-rules), and until it sends it, `limit` is `None` and the refusal's sentence is what says which limit. Since 0.112.0 `refusals` reads a 422 [`answer_not_parsed`](/api/errors/#answer_not_parsed): each answer an AI use refused, in order, as `{"word", "stop_reason", "output_tokens"}`; `None` for any other error. Pass `if_match=el["change_seq"]` to `patch` or `edit_links` to write only if nobody changed the element since you read it (since 0.2.0); if it moved, `PreconditionFailed` carries `current`, the element as it is now. See [Only if unchanged](/docs/development/api/writes#only-if-unchanged).
- **Export**: `export_world` (an account world to a folder; since 0.7.0 its `world.json` says where it came from and which part of the world it is, `source` and `exported_as`, read from `/me`), and `onlyworlds.okf.export_okf` (a folder to an OKF bundle, since 0.6.0).

**Not in the Python package yet**: typed element models, the account routes, `members()`, hiding, `adopt` (moving who made an element), images and files, `set_my_character`, sign-in, and the snapshot writer. For these, use the [TypeScript SDK](/docs/development/typescript), which has them, or call the [REST API](/docs/development/api-reference) directly. To ask for one, open an issue on [python-sdk](https://github.com/OnlyWorlds/python-sdk/issues).
