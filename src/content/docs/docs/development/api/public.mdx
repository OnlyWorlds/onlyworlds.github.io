A world's owner can open the world to everyone. Anyone can then read it with no key and no account: through the API, through tools that read worlds, and, if the owner gives it one, on a **public page** at `onlyworlds.com/w/<address>`. Both are off for every world until its owner turns them on.

Opening a world never shows what its owner [hid](/docs/development/api/hidden). The public reads every element that is not hidden, not [still proposed](/docs/development/api/proposals#the-switch) and not part of a world's chat room (its [room elements](/docs/schema/profiles#room)), with its fields, links and pictures. The others are missing, and so are the links to them and their counts; a new element an AI seat proposed shows once a keeper settles it.

## Turning it on

The owner turns it on in the **Settings** pane of the world's page on onlyworlds.com, in the card **Who can see this world**:

1. **See it as the public first.** **View as the public** shows the world exactly as a stranger gets it ([View as](/docs/development/api/hidden#view-as)).
2. The card lists what a stranger would get: the elements you have not hidden, with their fields and links; their pictures, "which anyone with the link can already open"; not their files ("for now"), not the roster of who plays whom, and not the elements you hid, "and every link and count that would show them". With nothing hidden, it warns instead: "You have hidden nothing yet, so every element would be public."
3. Pick one of two:
   - **Only people you invite**: "No one else can read this world." The default.
   - **Anyone can read it, with no account**: "Through Atlas, the API and tools that read worlds. It has no page."
4. Under the second, tick **Give it a public page at onlyworlds.com/w/…** and type its address. The card says **Free** or **Taken** as you type, and **Save** checks again.

A public page is public reading with a face: ticking it turns public reading on in the same save, and choosing **Only people you invite** closes the page too ("This also closes the page."). Turning either off works at once ("Turn it off any time and the door closes at once."): no public answer is cached anywhere on the way.

The demo worlds (Moppetopia, Hyperion and the others read with a [demo key](/docs/getting-started/keys)) are not their owner's to open or close: their world page has no such card, so they have no public page. Moppetopia is open to read, so the examples below use it.

### The address

- 3 to 40 characters: lowercase letters, numbers and hyphens, with no hyphen at either end and never two in a row.
- Unique across onlyworlds.com, first come first served.
- Not one of the site's own words (`about`, `start`, `tools`, `develop`, `docs`, `join`, `worlds`, `api`, `admin`, `static`, `account`, `w`, `agents`, `privacy`, `whatsnew`) and not an element type's name (`character`, `location` and the rest); not a world id in its written form (36 characters, four hyphens). Since 2026-11-13, 32 hex digits without hyphens are an address like any other and may be taken, except another world's id written that way: that is refused, while a world may take its own id's 32 hex digits.
- The page also answers at `onlyworlds.com/w/<world id>`, whatever address the owner chose. That address cannot be taken or changed. The id is read only in its written form; the same id as 32 hex digits without hyphens no longer opens the world (since 2026-11-13, as [the address profile](/docs/schema/profiles/addresses#an-address-in-prose) reads it).
- An address exists only while the page is on. Turning the page off frees it, and turning it back on asks for one again; "A name given up before may be taken by now." Changing the address frees the old one at once, with no redirect from it.

### The look

While the page is on, the card has a second form, **Look of the page**, all of it optional:

| Setting | What it does |
|:--|:--|
| **Palette** | One of five: Midnight (black and cyan, the default), Daylight, Parchment, Brass or Dusk |
| **Hero line** | One plain sentence under the world's name, at most 120 characters |
| **Sections** | Which element types show and in what order: tick an element type and number it. Untouched, every element type with something public shows, maps first, then Characters, Locations and Zones. An element type with nothing public never shows. Pins and Markers are parts of a map, never a section; a Zone is a place in the world and has its section |
| **Pinned element** | One element, shown in a card at the top, picked from a list by name: the elements the public reads, of every element type the page can show, as "Name (Element type)", sorted by name. A hidden element is never listed. A world with more than 300 such elements lists the first 300 by name and keeps a field for an element's id beside the list. A pinned element that is later hidden, deleted or still proposed drops off the page quietly, and the card tells the owner |

Search engines are kept off: every public page carries `noindex`, so a public world does not show up in search results. There is no setting to change that today.

## What a visitor sees

The pages need no sign-in and are plain HTML with no script, but for the graph, read on the same terms as the [keyless API](#the-keyless-reads): everything not hidden or still proposed, nothing of the world's members.

- **The world's public page**, `/w/<address>`: the world's picture, its name, the hero line and description, a row of links to each section with its count, the pinned element, then each element type with its first four elements as cards and the full count beside the heading. An element type with one or two elements goes in a short list under **Also here**. A map has a section of its own however few there are. The row of links shows only when the page has two or more sections of their own, and links only to those, never to **Also here**; on a phone it wraps. The pinned element shows once, in its card: its element type's section and **Also here** leave it out, and the next element takes its place. The footer says when the world last changed, and the top bar links **Made with OnlyWorlds** to onlyworlds.com.
- **An element's public page**, `/w/<address>/<category>/<element id>`, the element id in its written form (since 2026-11-13: the same id as 32 hex digits, in braces or as `urn:uuid:` answers `404`, for the owner too): its picture, its name, its element type, supertype and subtype, its description, **Details** and **Connected to**, both drawn from its own element type's fields in the schema's order (since 2026-11-07; before, every page used a Character's fields). Details holds every text field that is set, then every number that is set (a `0` shows); Connected to holds every link field, a row only when it points at a public element. A long text keeps its line breaks, in Details and in the description alike: a blank line starts a new paragraph and a single break starts a new line (since 2026-11-10). A link to a hidden element is not there, and a Pin's generic link is no row. The path above it, back to the world's page and its element type's section, shows only when the world page has two or more sections of their own and its element type is one of them.
- **The address read whole** (since 2026-10-29): an element's public page takes the [human address](/docs/schema/profiles/addresses) with a moment (`@<step>`) or a lens (`?lens=<id>`) on it, and a malformed moment or lens answers the page's 404. The world's owner, signed in, is sent on to the element's page in their own account (`302`), and so is a signed-in member whose role reads the element, to their own read-only page for it; a member whose role does not reads the public page as anyone does. The world's own address sends its owner, signed in, on to the world in their account, and since 2026-10-30 every signed-in member, at any role, to their own page for the world, whether its public page is on or off. An AI seat has no account on the site, so its world reads there as anyone's does. A public Pin or Marker sends the visitor to the world's page; a Zone has a page of its own (since 2026-10-30). An element's page names its canonical address by the world's id.
- **The world's graph**, `/w/<address>/graph`, linked as **Graph** on the public page's bar: every public element as a point and every link as a line, drawn in the browser by the page's one script, each point opening its element's public page. Since 2026-11-02 the page draws what the [graph reader](/docs/lenses/graph) reads: a link from an element to itself is a small loop, a field that names one element twice is two lines, and a link to an element of the wrong type for its field is not drawn. Maps, Pins and Markers are left out, with every line to one. The charter, its guide and its domains are never points. A Zone is a point like any other (since 2026-10-30). It reads the same public view, so what is never shown below is not in it.
- **The landing file** (since 2026-11-02), `/w/<address>/landing.json`: the world's first picture as the [landing profile](/docs/schema/profiles#landing) reads it from the same public graph. It holds the profile's five keys in order (`mode`, `size`, `clusters`, `unclustered`, `gaps`), then `lenses` (each lens the owner chose for the landing: its id, its name, and the member ids a visitor may see; an entry of `x_landing.lenses` is read as written, so one in another spelling than the lens's id greets nothing, since 2026-11-13), `baked` (`{heads, hops, head}`, where `head` is the world's change number it was read at) and `world` (`{id, name}`). The graph page's own file carries the same `head`, so a page that draws from both can tell they were read at one state; an id the landing names that the graph file lacks is the drawing's to drop, reading both again.
- **Cited by** (since 2026-10-29), on the world's public page: the public worlds whose public text holds an address of this world (`ow://<world id>/<type>/<id>`, `ow://<world id>`, or its `onlyworlds.com/w/<world id>` address), each with how many of its elements do and up to five of them by name. A private world that cites it never shows, not even as a count, and with no public citer the section is not there at all. The index is rebuilt from an element's text on every write of it; the addresses are recorded as written and never resolved.
- **Never shown**: hidden elements and the links and counts that would show them; a world's chat-room elements (`x_room_of`, the [room profile](/docs/schema/profiles#room)); elements still proposed (`x_review_proposed` with a value that counts as present: not `null`, an empty string or whitespace alone, `[]` or `{}`) until a keeper settles them; who a review mark names (since 2026-11-11 a public element's `x_review_checked` is served with `by` `null`, its other keys as stored; an element whose `x_review_proposed` holds a value is not served at all, and a settled one carries it empty); files; the roster; deleted elements.

For a reader signed in on onlyworlds.com, every world address that answers nothing gets the same page, status `404`: a mistyped address, a world whose page is off, and a private world. It reads "This world has no public page. The address may be mistyped, or the owner has not turned the page on. If someone sent you this link, ask them to check it.", so it says nothing about whether a world exists.

A signed-out reader is sent to sign in instead (since 2026-11-02): a `302` to the sign-in page that carries the same address, moment and lens included. After signing in, a member of the world lands on their own page for it, and anyone else meets the `404` page. A made-up address is sent on the same way, so neither answer says whether a world exists. This holds for the world's page, an element's page and the graph page; `graph.json` and `landing.json` stay a `404`.

Under a live page, every element address that answers nothing gets one other page, also `404`: a hidden, deleted or unknown element, a wrong element type, a garbled id. It reads "This page isn't available." and links back to the world's page by its name, the same bytes for every case, so it says nothing about whether an element exists.

Every answer, the `404` included, carries `Cache-Control: no-store` and `X-Robots-Tag: noindex`. A link shared in a chat unfurls with the world's or element's name and the hero line (else the description's first sentence); the canonical address is the one with the page's address when it has one. Page reads count against the same budget as keyless API reads: 60 a minute per address ([Limits](/docs/development/api-reference#limits)), over it a `429`. {/* limit: requests_per_minute_keyless */}

## The keyless reads

A request with no `API-Key` header and `?world=<world id>` reads an open world as the public:

| Method | Route |
|:--|:--|
| GET | `/api/v2/{type}` and `/api/v2/{type}/{id}` ([Reads](/docs/development/api/reads)) |
| GET | `/api/v2/search` ([Search](/docs/development/api/reads#search)) |
| GET | `/api/v2/world` ([The world](/docs/development/api/reads#the-world)) |
| GET | `/api/metadata/{type}/` and its sections, and the same under `/api/worldapi/metadata/` |
| GET | `/api/v2/character/{id}/context` ([The draught](/docs/development/api/draught)): what the public may read about her, never her messages or the roster |

```bash
curl -s "https://www.onlyworlds.com/api/v2/character?world=0695db52-5433-7332-8000-db7fe10da375&limit=5"
```

That is Moppetopia. The answer is what the owner's own key gets with [`?as=public`](/docs/development/api/hidden#view-as):

- **Hidden elements are missing.** A list leaves them out, a `GET` of one is `404` [`not_found`](/api/errors/#not_found), and links to them are left out of every body. Room elements are left out the same way, and so are elements still proposed (`x_review_proposed` with a value that is neither `null` nor empty) until a keeper settles them: nothing says one is missing.
- **A deleted element is `404`**, never `410`: the public reads no tombstones.
- **`image_url` is served** as any field is: a picture is public by its own link.
- **The query parameters work as with a key**: filters, `limit`, `cursor`, `?expand=`, `?fields=`.

### The world, keyless

`GET /api/v2/world?world=<id>` carries the world's own fields, with `owner_character` always `null` (the public gets no roster) and `counts` beside them, counted as the public reads them:

{/* shape: GET /api/v2/world partial */}
```json
{ "id": "0695db52-…", "name": "Moppetopia", "public_read": true, "owner_character": null,
  "slug": null, "public_page": { "on": false, "palette": null, "hero": "", "sections": [], "pin": null, "index": false },
  "counts": { "total": 319, "types": { "ability": 1, "character": 23, "location": 32, "marker": 131 } } }
```

(Shortened.) Here `world` may also be the page's address: a world's id in its written form (36 characters, four hyphens, hex in either case) is the id, and any other value, 32 hex digits without hyphens included (since 2026-11-13), is tried as an address, which names a world only while its page is on. The element, search and metadata routes take the id only.

### What it does not serve

- `/changes`, `/members`, `/me`, files, the hidden routes and every write answer a keyless request as before: `401` [`invalid_credentials`](/api/errors/#invalid_credentials). The [MCP server](/docs/development/mcp)'s read and write tools answer a keyless call with a tool error, "API-Key header required." (HTTP `200`, `isError: true`); its schema tools need no key. The [proposals](/docs/development/api/proposals) lists answer it `404`. A follower who wants the live feed needs a read key.
- An element read keyless carries no `created_by`, `changed_by`, `changed_via`, `changed_client` or `doors` (since 2026-10-29): who wrote an element, and with which tool, is for the world's members. A keyless `created_by=` filter is a `422` naming it.
- A keyless request without `?world=` is the `401` it always was.
- `as` on a keyless read is `422` [`invalid_request`](/api/errors/#invalid_request), `param` `as`: view as is the owner's.

### Answers

- **One `404` for every closed door.** A world that is not open to read, an unknown id and a value that is no id at all answer the same `404` [`not_found`](/api/errors/#not_found), "World not found.", so the answer never tells whether a world exists.
- **With a key**, `world` naming the key's own world by its id is ignored, and any other value, an address or the same id as 32 hex digits without hyphens included, is `422` [`invalid_request`](/api/errors/#invalid_request) with `param` `world`: a key reads its own world only.
- **`Cache-Control: no-store`** on every keyless answer, errors included, so turning public reading off closes the door at once. `ETag` and `If-None-Match` work as with a key.
- **The budget**: 60 a minute per address, shared with the public pages ([Limits](/docs/development/api-reference#limits)). {/* limit: requests_per_minute_keyless */}

The [TypeScript SDK](/docs/development/typescript) reads a public world with no key: `new OwV2Client({ world: id })` (since 4.88.0; reads only). The [Python package](/docs/development/python) sends a key on every read and has no keyless call yet; there a keyless read is a plain HTTP `GET`.

### How big OnlyWorlds is

`GET /api/v2/public/counts`, with no key (a key sent is ignored), answers the platform's totals, for a page that shows them read rather than typed:

{/* shape: GET /api/v2/public/counts */}
```json
{"worlds": 550, "public_worlds": 0, "elements": 46838, "kinds": 22, "public": [], "counted_at": "2026-10-25T12:13:25+00:00"}
```

`worlds` and `elements` count every world, private ones included, which are never named; `kinds` is the standard's number of element types; `public` lists the newest 50 worlds whose owners turned public reading and the public page on, each with `name`, `address` and `elements`, the count its public page shows (hidden, room and still-proposed elements left out); `public_worlds` counts them. It is counted at most once a day (`counted_at`), except that an owner turning a world's public reading or page on or off drops the held count, so the next read counts again (since 2026-10-29); it is sent with `Cache-Control: public, max-age=3600`, so a browser or cache may hold the old answer up to an hour.

## On the wire

[`GET /api/v2/world`](/docs/development/api/reads#the-world) carries three keys for all of this, with a key or without:

{/* shape: GET /api/v2/world partial */}
| Key | Meaning |
|:--|:--|
| `public_read` | `true` when the owner chose **Anyone can read it** |
| `slug` | The page's address, `onlyworlds.com/w/<slug>`, or `null` while the page is off |
| `public_page` | The page as the owner set it: `on`, `palette`, `hero`, `sections`, `pin`, and `index` (always `false`). Every key is present while the page is off |

All three are the owner's to set on the world page and are read-only on the API: a `PATCH /api/v2/world` carrying any of them is `422` [`invalid_request`](/api/errors/#invalid_request), like any field it cannot write. A tool that writes a world body back strips them. No tool can open a world or give it a page.
